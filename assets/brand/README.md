# AIVITA — набор логотипов

Бренд-ассеты AIVITA (2026-05, из `AIVITA_Logos.zip`) плюс два отдельных файла логотипа. Набор используется **как есть, без перерисовки**: неоновый крест — в иконках и аватарах, маскот (робот) — в горизонтальном логотипе. Это уже согласованное решение, а не временная заглушка.

Это склад ассетов, а не то, что подключено в приложениях. Замена текущих логотипов в apps/* — отдельная будущая задача.

## ⚠️ Известный брак: `horizontal/` пока нельзя использовать

**Все 6 файлов в `horizontal/`** (300×99, 400×132, 600×198, 800×264, email_200, 1024×339) **испорчены — не берите их для новых мест, пока набор не переэкспортирован.** Переэкспорт делает Фарход из своего исходника, срок не зафиксирован.

Проверка (2026-09-19) показала не один и тот же баг «в одном месте», а **три разных, независимых повреждения** одного и того же горизонтального логотипа — в наборе и в двух местах, где он уже живёт на проде:

| Файл | Где | Альфа-канал | Что именно сломано |
|---|---|---|---|
| `horizontal/aivita_logo_300x99.png` ... `horizontal_1024x339.png` (все 6) | этот набор | нет (чистый RGB) | Шахматный узор прозрачности (из окна редактора) запечён прямо в обычные пиксели фона — не прозрачность, а картинка клетки |
| `apps/aivita/public/logo.png` | шапка/подвал маркетинговой части aivita | нет (RGB) | **Тот же брак, тем же файлом** — побайтово идентичен `horizontal/aivita_logo_horizontal_1024x339.png` из этого набора |
| `apps/admin/public/logo.png` | сайдбар админки | нет (RGB) | **Тот же брак**, побайтово идентичен предыдущему |
| `apps/landing/assets/logo-horizontal.png` | шапка/подвал лендинга, все 90 страниц | есть, используется | Отдельный, третий по счёту баг: кольцо и текст вырезаны прозрачностью чисто, а маскот внутри круга — нет: его альфа-канал выведен из яркости самой фотографии, а не из маски объект/фон, поэтому лицо/волосы/халат местами пятнами полупрозрачны. На светлом фоне лендинга (~#faf9f7) незаметно, на тёмном или цветном — будет видно пятнами |
| `apps/aivita/public/brand/aivita-logo-transparent.png` | `TopBar.tsx` — шапка приложения на каждом экране после входа, самое видимое место логотипа в продукте | есть, используется | Третий, отдельный и самый грубый вариант: мелкая клетчатая сетка запечена **в самом альфа-канале** (не в цвете), лицо маскота съедено сильнее, чем в версии лендинга, плюс посторонний артефакт — треугольник, наезжающий на буквы «TA» |

Ни один из этих трёх файлов не совпадает с другими побайтово — это три отдельных, независимо испорченных экспорта одного и того же логотипа, не один баг с одним источником. Значит переэкспортировать нужно все три места отдельно (или заново раздать один чистый мастер-файл во все три), простое копирование одного файла поверх другого проблему не решит.

`social-avatars/` и `app-icons/` этой болезни не имеют — там либо чистая непрозрачность (обычный светлый фон, это дизайн, не брак), либо для двух файлов (`aivita_icon_transparent_1024x1024.png`, `aivita_icon_notification_silhouette_96x96.png`) настоящая, корректная прозрачность.

## Важно: прозрачность

Изначально из всего набора реальную прозрачность имел только `Aivita_logo.png` (431×431). Всё остальное — `app-icons/*`, `social-avatars/*`, `horizontal/*`, включая `aivita_icon_1024x1024.png` — непрозрачный PNG в режиме RGB. Для `app-icons/*` и `social-avatars/*` это нормально — светлый фон там запечён намеренно, это дизайн, не брак. **Для `horizontal/*` это не нормально** — там вместо чистого фона запечён шахматный узор прозрачности, см. раздел «⚠️ Известный брак» в начале файла.

Для тёмных тем нашлась уже готовая прозрачная версия того же знака — она лежала в `apps/mobile-patient/assets/` и `apps/mobile-doctor/assets/` (побайтово идентична в обоих приложениях), просто не была скопирована в общий набор. Теперь она здесь: **`app-icons/aivita_icon_transparent_1024x1024.png`** (1024×1024, RGBA) — используйте её для иконки приложения/логотипа на тёмном фоне вместо запекания нового файла с нуля. Для push-уведомлений Android есть отдельный упрощённый силуэт — **`app-icons/aivita_icon_notification_silhouette_96x96.png`**.

Горизонтального логотипа с прозрачным фоном по-прежнему нет ни в каком виде — если он понадобится (например, для тёмной темы сайта), его придётся заказать отдельно.

## Что не входит в этот набор

**Маскот AIVITA** (иллюстрация «лица»/робота, используется на лендинге как `aivita-face-v3.png`, `aivita-robot-hero.png`, `aivita-robot-cutout.png` в `apps/landing/assets/`) — это отдельный визуальный элемент, не входящий в этот набор. Набор в `assets/brand/` содержит только знак (крест в круге) и вордмарк; маскот живёт и обслуживается отдельно на лендинге.

## Чего не хватает (известные пробелы)

- **og-image 1200×630** — карточка для превью ссылки в соцсетях (Open Graph/Twitter). Это не логотип, а отдельная маркетинговая композиция — простого файла с логотипом на цветном фоне для этого недостаточно, нужен отдельный дизайн-проход.
- **Промежуточные размеры иконки 128×128 и 384×384** — в наборе есть 1024, 512 (playstore), и полный набор Android/iOS-размеров, но не эти два конкретных значения (они нужны для `apps/aivita`'s PWA-манифеста — см. отдельный отчёт по их исправлению).
- **Горизонтальный логотип с прозрачным фоном** — есть только непрозрачные варианты (см. выше).

## Происхождение

Файлы распакованы из `AIVITA_Logos.zip` (41 запись = 37 файлов + 4 записи-папки). Оригинальные имена папок внутри архива были в кодировке, которая не читается штатными средствами Windows (ни cp437, ни cp866, ни windows-1251 не дают осмысленный текст) — папки идентифицированы по числовому префиксу (`1_`, `2_`, `3_`) и по составу файлов, и переименованы на этом основании:

- `1_...` → `horizontal/` (горизонтальные варианты логотипа)
- `2_...` → `social-avatars/` (аватары соцсетей)
- `3_...` → `app-icons/` (иконки приложения + favicon)

Имена самих файлов внутри папок не менялись.
